Framework demo & reference

wavefw WaveDrom JSON → interactive waves

A dependency-free renderer for the WaveDrom format with two outputs from one model: the interactive canvas viewer of the PSI5 datasheet (docs/reference/template.html) and a static WaveDrom-style SVG for figures. Waves are written by hand or converted from a simulator dump with wavepeek. Everything on this page renders from file:// with one script and one stylesheet.

1. Overview

wavefw.js parses WaveJSON (the input of the WaveDrom editor) into one time-ordered transition list per signal. Two painters draw that model with the same routine, so a figure and a viewer of the same data look alike:

  • WaveView: a canvas viewer with a name column showing values at the cursor, wheel zoom at the pointer, drag to pan, click to set the cursor, keyboard control, markers, jump buttons and groups you can fold.
  • WaveSVG: an inline SVG that follows the page's light/dark tokens (var(--wave-1), var(--wave-bus) …) and stays sharp when printed.

Two small extensions keep stock WaveDrom compatibility. "time" maps cycles to picoseconds, so the axis shows real time. The per-signal "tv" list carries exact transitions from a dump. Stock WaveDrom ignores both keys.

4. Interactive viewer


The same parser feeds WaveView. Without the time extension the axis counts cycles, starting at head.tick. Markers and jump buttons come from the optional markers and jumps keys. Click a group header (▾) to fold it.








Sorting signals


The Sort button cycles off → A→Z → Z→A (key s on the canvas). The field next to it lists name prefixes that are skipped when names are compared, so with i_,o_ the signal i_valid sorts as valid; the skipped prefix is drawn dimmed. Names compare naturally (d2 before d10), groups move as a block and their members are sorted inside, and a {} spacer splits the list into runs that are sorted separately. To start sorted, use "config": {"sort": "asc", "sortIgnore": ["i_", "o_"]} in the JSON, data-sort="asc" data-sort-ignore="i_,o_" on the element, or the settings file. Static SVGs take the same keys.








Highlighting instances


Each name row has a small mark ○ in its left gutter (it shows on hover). Click it, or ctrl/⌘+click the name, to highlight that signal or group: a group covers all its members, nested groups included, so one click picks a whole instance. The highlighted rows stay in front, tinted in their own colour with a bar at the left edge. The other rows fade to the background (the dim setting, 0.3) but stay visible, and the headers of the groups that contain a highlighted row stay in front too. Several instances can be highlighted at once, each in its own colour (six colours, then they repeat). Highlight: N ✕ in the bar or Esc on the canvas clears it. To start highlighted, set "config": {"highlight": ["tx", "*.irq"]} in the JSON, data-highlight="tx" on the element, or the setting in a config file. Entries are full paths (tb.dut.u_tx), names, or * patterns, one colour per entry. Static SVGs take the same setting.








Cursor time and window


The cursor group in the bar takes a time: type a number in the unit chosen next to it (ps, ns, µs, ms, s), or a time with its own unit such as 85.12us, then Enter or Set; the cursor goes there and the view follows when needed. The second field is a span: Enter or Show (key c on the waves, with the current span) shows a window of that width centred on the cursor. Both fields follow the cursor and the view while you are not typing in them; diagrams counted in cycles take cycles.



Fuzzy find


The find field in the bar (key /) searches like fzf / telescope in nvim: the typed letters in that order, anywhere in a name (rqv finds req … valid-like names, txd finds txd and tx_data). A word with a . runs over the full path, and words separated by spaces must all match. Matched letters are underlined; Enter / shift+Enter, the ‹ › buttons or n / N on the waves (as in vim) go to the next / previous match, Esc anywhere in the viewer clears the search, every highlighted row and the selected signal, and leaves the view where it is (ctrl+C on the waves ends a search too) (switch Open off to get the earlier folding back). Copy puts the full paths of the found rows on the clipboard. Names selected with the mouse copy as clean full paths too (one per line), and with no search running ctrl+C on the waves copies the selected signal. The options apply while you type: Highlight puts the found rows in front and dims the rest, Open folds every module except those that contain a match (the earlier folding comes back when the search is cleared), and the colour next to Paint recolours the found signals (kept in this browser; Unpaint undoes it). Try val or bus.d in the viewer below.



Edge search and bookmarks


Click a signal name, or a row on the waves, to select it (↑ ↓ move the selection). ◀ ▶ in the bar ([ ]) move the cursor to the previous or next edge of the selected signal; the list between them (e) picks ↕ any edge, ↑ rising or ↓ falling. A bus has no direction, so there every value change counts. With no signal selected the search takes the nearest change of any shown signal. + Mark (m) puts a numbered bookmark on the selected signal at the cursor, snapped to an edge within 6 px. Below the waves each bookmark has a line: its time (type 250ns, 85.12us, or a number in the unit shown; cursor moves it to the cursor), its signal (or — axis), the edge found there, a colour (the accent colour unless changed) and a text field for describing the event. On the waves, drag a circle to move the bookmark: left/right changes the time (snapped to an edge of that row), up/down moves it to another signal row or onto the time axis. Shift+drag from one circle to another draws an arrow between them; + Arrow adds one between the last two bookmarks. Each arrow has its from → to, a shape (WaveDrom edge shapes: - straight, ~ curve, -~ ~- curves bending late or early, -| |- corners, -|- step), a head (end, both, start, none), a line (solid, dashed, dotted), a colour and a label; click an arrow on the waves to edit its label. Any number of arrows can leave or reach one bookmark. An arrow's label goes into a thin lane of its own, inserted between the signals under the upper end of the arrow (above the row when both ends are on it), so the text never covers a wave; several labels at one place stack in the lane. The laneHeight setting sets its height per label (16 px), and arrowLabels: "overlay" puts the labels back on the arrows. Click a number, in the list or on the waves, to go to that bookmark. Bookmarks and arrows are kept in this browser (localStorage). JSON gives them as "bookmarks" and "arrows" lists for the WaveJSON or a config file, so a generated page and its static SVG carry them; the SVG adds a legend with the texts. Expand / Collapse open or fold every group at once.








Edge styles and radix


The style setting draws edges WaveDrom-like (wavedrom: slanted 1-bit edges, <> bus ends) or like a simulator's wave window (questa: vertical edges, narrow bus crossings; square: vertical edges, square bus ends). auto, the default, slants WaveDrom wave strings and draws exact tv transitions vertically. The radix setting (auto | hex | dec | signed | bin | oct | ascii) formats bus values from tv; auto shows up to 6 bits in decimal and wider buses in hex. Both settings also exist per signal ("style", "radix" in the signal object) and override the global value. The three figures below render the same JSON with data-config='{"style": "…"}'; each bus row sets its own radix.

5. Themes and colours

6. From a simulator dump


The data below comes from examples/demo/demo_tb.sv, a small Manchester transmitter (2 start bits, 8 data bits LSB first, even parity, 100 MHz clock, 8 clocks per bit). Verilator writes the VCD, tools/vcd2wavedrom.py reads it (built-in reader, or wavepeek), and tools/embed.py packs the JSON into docs/demo_waves.js. make demo runs the whole chain.



Exact transitions, interactive


Every edge is drawn at its real timestamp (the tv extension). The markers are the results of wavepeek change --on 'posedge start' and 'posedge done', and the viewer turns each marker into a jump button.





Same dump, one byte as a static figure


The first byte, cut out of the same model with data-from/data-to and drawn by WaveSVG. This is how the "frame anatomy" figure of the PSI5 datasheet can be produced from data.





Clock-sampled, plain WaveDrom


With --clock clk the converter samples every rising edge and writes ordinary wave strings, which stock WaveDrom also renders. --gap 100ns:250ns folded 15 cycles into one | cell. The time.skip entry keeps the time axis correct in the viewer.

Settings (config file)


Colours, sizes, fonts, line widths and sorting are settings. They are merged in this order, later wins: built-in defaults, the global settings (wavefw/wavefw.config.js loaded before wavefw.js, which sets window.WAVEFW_CONFIG, or WaveFW.configure()), the diagram's "config" object, and the element's data-* attributes or the constructor options. The "config" section of a converter config file (examples/demo/demo.config.json, work/dump.config.json) is written into the generated JSON; tools/mkhtml.py uses the top-level one as the page's global settings. This page loads wavefw.config.js.




KeyMeaning


theme, colorsAs in section 5. Global: applied to <html>.


rowHeight, groupHeight, spaceHeight, headerHeightRow heights in px (26, 22, 14, 24; static SVG group/spacer rows default to 20 and 12).


nameWidth, fontSize, labelSizeViewer name column (200 px), name text (11.5 px), bus labels (11 px).


fontMono, fontBodyCSS font-family lists (set --font-mono / --font-body).


traceWidth, busWidthLine widths of 1-bit traces (1.4) and bus outlines (1.2).


sort, sortIgnorenone | asc | desc and the prefixes skipped when sorting (array or "i_,o_").


sortButton, hintShow the Sort controls and the help line (both true).


style, radixEdge style auto | wavedrom | questa | square and bus value radix auto | hex | dec | signed | bin | oct | ascii (see section 4). A signal's own "style" / "radix" wins.


groupColorsOne colour per group, e.g. the channels of a bus: {"aw": "#339af0", "w": "#37b24d", "tb.dut.u_rx": "#ae3ec9", "*fifo*": "#f59f00"} (group names, full paths or * patterns; the nearest matching group wins). The signals take it as trace, bus outline and name colour, the group its name colour; a signal with its own color / stroke keeps it. Static SVGs follow it.


highlight, dimInstances highlighted at start (full paths, names or * patterns; a group covers its members; one colour each) and the opacity of the other rows (0.3). Colours: hl1…hl6 in colors.


groupOrder, moduleShadinggroupOrder: "last" lists the signals of every group first and its sub-groups (modules) after them ("first": the other way round, "file": as given), also when sorted; generated configs use "last". moduleShading (default on): the signals of neighbouring modules alternate between two backgrounds, with a line where the module changes.


maxHeightFor example "80vh" or 600: the rows scroll inside the viewer and its bar stays in view. Any number of rows works: the canvas only covers the visible part and the time axis stays on top.


arrowLabels, laneHeightlane (default): bookmark arrow labels get a thin row of their own between the signals, laneHeight px per label (16); overlay: on the arrow.


foldGroups folded when a viewer opens: true (all), a nesting depth (2: groups inside groups inside groups) or group paths (["tb.dut"]).




Extensions to WaveJSON




KeyMeaning


time: {t0, cycle, t1?, skip?}Cycle c starts at t0 + c·cycle ps. skip: [[k, n]] means the | cell at index k stands for n cycles.


signal[i].tv: [[t, v], …]Exact transitions in model time. 1-bit values are 0 1 x z; buses are hex strings. Takes precedence over wave.


signal[i].width, enum, radix, style, colorBus width, value labels, value radix (fmt is an alias), edge style, fixed fill colour 3–9 (a CSS colour string in color acts like stroke).


signal[i].path, sameFull hierarchical path (shown as the name's tooltip). "same": "path" takes the tv of the signal with that path, so one net seen at several levels is stored once.


signal[i].stroke, fillCSS colours for this signal's trace/outline and bus fill. The name is drawn in the stroke colour.


config.theme, config.colors, config.*Theme, palette (same keys as data-colors) and any other setting for this diagram.


bookmarks: [{n, t, signal, text, color}]Numbered events: t in model units (or a time string), signal the full path (group.name), a CSS colour (default: the accent). Static SVGs add a legend with the texts.


arrows: [{from, to, shape, head, line, color, label}]Arrows between bookmarks n: shape - ~ -~ ~- -| |- -|- (default ~), head > <> < or "" (default >), line solid dashed dotted.


markers / jumps / cursor{t | cycle, label} and {t | cycle, span, label}; t is in model units or a time string.






9. Reproduce


make demo        # verilator --binary --trace  ->  $(BUILD)/demo.vcd   (BUILD ?= /tmp/wavefw)
                 # tools/vcd2wavedrom.py --config examples/demo/demo.config.json  ->  docs/demo_waves.js
make examples    # examples/apb, axi_lite, fsm: VCD + FST, a page from each config, a page of the whole hierarchy
                 # ->  $(BUILD)/examples/<ex>/<ex>.html, <ex>_all.html   (make example EX=apb: one of them)
make html        # tools/mkhtml.py: every view of the config  ->  one self-contained page ($(BUILD)/demo.html)
make html CONFIG=work/dump.config.json HTML=work/dump.html     # the same for any dump
make html WAVES=work/test_stream_video.vcd           # from the VCD alone: makes work/test_stream_video.config.json
                                                     # (every signal, full paths, editable) and work/test_stream_video.html
make demo-fst    # the demo as FST (verilator --trace-fst): FSM states named from the dump's enum tables
make html WAVES=x.vcd SV="rtl/*.sv"                  # VCD: enum labels from typedef enum in the sources
make smoke       # headless Chromium (playwright): no console errors, interaction checks, screenshots
make shots       # the README screenshots in docs/img/ (tests/shots.py)

python3 -I tools/vcd2wavedrom.py --waves dump.vcd --scope tb.u_dut --exact \
    --from 896us --to 1155us --signals i_sat_rxd_comp,r_state,o_sat_data \
    --enum r_state=0:IDLE,1:VERIFY,2:RECEIVE,3:GAP,5:ERROR \
    --marker 'posedge o_sat_data_eof=eof' --out frame.json


To cross-check a window in a GUI, open the same VCD in Surfer and compare the edge times at the markers. Surfer is not needed to build the page.
