Guide

Compare two runs

The same test before and after a change of the RTL, or with another seed: Compare… reads the second run's dump over the waves you have open and marks, signal by signal, where the two differ. A red band on the row, ≠ on the name, and ]d to go from one difference to the next.

The example: run B of the APB testbench

The pictures compare the APB example (make examples, the view the whole run · exact transitions of out/examples/apb/apb.html) with a run B made from its VCD by tests/guide_shots.py: in B the read at 115 ns returns 0xDEADBEEF, the slave's PREADY for the write at 155 ns comes 10 ns later, and PSLVERR is not in the dump at all. Three kinds of difference, each the way a real regression shows.

Loading the second dump

  1. Open the page with the first run (A). The compare works on exact waves — a page made with --exact, the exact view of an example, a dump opened in wavelens/viewer.html. A clock-sampled view refuses: one cell per cycle is another time scale.
  2. Compare… in the bar's dump group, then pick B's VCD. An FST: turn it into VCD text first, bin/linux-x86_64/sva vcd b.fst --out b.vcd (in VS Code the extension does that for you).
  3. The signals are matched by their path; else by their name under the page's scope; else by the one path of B that ends with the name. One found by its short name only (tb.a.ready as tb.b.ready) is still compared but said: matched by name: tb.a.ready → tb.b.ready in the toast and in the tooltip of ≠ N ✕.

Reading the differences

On the wavesMeans
a red band on a rowover that stretch B holds another value (the stretch shaded, a line under it)
≠ after a namethe signal differs somewhere in the time both dumps cover
a struck nameB has no such signal (one B's reader left out for dumpBudget is said apart in its tooltip)
≠ N ✕ in the barN signals differ (the title line says where the first one is); ✕ compares no more

Values are compared as values, not as text: bit for bit, x and z apart, so an unknown that became known is a difference; a bus of another width differs everywhere; a real as a number (inf, -inf, nan are three values); a string as text; a packed struct by its whole vector (≠ on its group); the bits of a bus (B) each by its own values, with its own bands and ≠. Only the time both dumps cover is compared; the toast says so when B is shorter. A result made elsewhere (a saved state, an agent's) is cut to the page's time. A dump with no signal in common compares nothing, and says so: the compare before it stays.

Going through them

]d / [d move the cursor to the next / previous difference: of the selected signal when it has some, else of every signal.

Flipping between the runs

With a dump compared the bar has A B A+B, and the time axis names the run shown on its colour, so the name stays in sight with the bar folded or scrolled away.

  • d flips the waves between A and B. B's values go on these rows in place: the rows that differ change, a row B has not got, or of another width or kind, is empty, the time B does not cover is shaded, the colours stay. Held on one stretch, only the difference moves. The value column, the edge keys, the find and the FSM panel read the run shown; the assertions stay A's.
  • D puts both over each other where they differ: a bit's B over its A in B's colour, a bus's row in two lanes, A above B, each with its value; the value column says 1 ≠ 0. D again: the run before.

]d [d work in all three. An agent does the same with the command compare: {"op": "compare", "show": "overlay"}, "b" or "a", and the picture is of the run shown.

Pictures and what is kept

The picture of the view (the right button's PNG / SVG, the picture command) draws the bands, so a regression can go into a review as it is:

A compare is kept: Save page and Save write its result (not dump B) into the page or the state file, so who opens it sees the bands. A page can also be built with them: the config's "compare": {"dump": "b.vcd"} runs sva diff when the page is made (below), carries B's values of the signals that differ, up to 32 MB, for B and A+B, and "show": "overlay" opens it that way. A compare of a dump read in the page has them for the session: saved, it keeps the bands.

A large B is read once, only its signals that could be the page's rows and only over the page's time; the toast says how far it is, and ≠ … ✕ in the bar stops the read.

The runs kept (VS Code)

A simulator writes its dump over the last one, so the run before is gone once you run again. Keep the runs you want to look back at, by hand, and step through them over one window:

  1. Runs… in the bar's dump group (g u, or WaveLens: The runs kept of this dump) opens the Runs panel. Keep this dump…: a name (the dump's by default), tags and a comment; the dump as it is on the disk goes into .wavelens-runs beside it as an FST (a VCD converted, the FSM states of its x.types.json kept), listed in runs.json. The directory has a .gitignore of its own: git leaves it out. wavelens.runsDir puts it elsewhere (a folder of yours: only the runs' files ignored, and the panel lists this dump's runs).
  2. Choose the window: over the waves in sight, or one of your spans (a test case: the spans of cocotb's marks, "every" in a config).
  3. Click a run (or ↑ ↓ in the list, ] r / [ r anywhere): these waves are compared with it over that window only, and only that window of the run is read — a run of gigabytes costs the window, not its size. Then it is a compare as above: the bands, ≠, ]d [d, A / B / A+B, and the view you chose stays from run to run.
  4. ↑ ↓ in the list compare once you stop on a run. The dump read again after a new simulation keeps the panel and compares with the run again; the status says equal, or what differs first, and why the run's values are not shown when they are not.
  5. Δ all asks every run at once: how many signals differ in the window and the first difference, on each run's row (red: some). The run where it broke stands out.
  6. Test cases: a run keeps its cases (your labelled spans when kept, or cocotb's wavelens.marks.json beside the dump). Choose the span of a case (the choice says · a case) and each run is compared over its case of that name, wherever it is in the run — the cases before it may have taken longer — over the shorter of the two. sva runs diff tb.vcd --case test_scratch in the shell, case for wave_runs.

✎ changes a run's name, tags or comment, ✕ removes it with its file (VS Code asks first). The runs are of the same test: signals by their path, the same time. In the shell the same list: sva runs keep tb.vcd --name golden --tags seed1, sva runs, sva runs diff tb.vcd --from 4us --to 6us (a line per run), sva runs path golden for sva diff; an agent has wave_runs. A run kept from a VCD is written in blocks of 1 MiB: a window late in a long run reads the blocks from there on, as fast as one at its start.

From the shell

The page keeps B's signals in memory. For dumps of hundreds of MB, for CI, or for two testbenches whose scopes are named apart, compare them in the shell: sva diff reads both as streams, neither in memory, and compares their values as Compare… does (two VCDs of 214 MB in 7 s):

sva diff apb.vcd apb_b.vcd --limit 4
A: apb.vcd  0 ps … 205 ns, 61 signals
B: apb_b.vcd  0 ps … 205 ns, 58 signals
58 signals compared, 3 only in A, 0 ps … 205 ns
398 changes compared, 6 differ in 6 signals; the first at 115 ns: apb_tb.PRDATA A=0xcafe0001 B=0xdeadbeef
          115 ns  apb_tb.PRDATA  A=0xcafe0001 B=0xdeadbeef
          115 ns  apb_tb.u_master.PRDATA  A=0xcafe0001 B=0xdeadbeef
          115 ns  apb_tb.u_regs.PRDATA  A=0xcafe0001 B=0xdeadbeef
          155 ns  apb_tb.PREADY  A=1 B=0
  … and 2 more (--limit)

The same three differences as on the page: PRDATA at 115 ns (on each of its three paths), PREADY at 155 ns, and PSLVERR only in A. The exit status is 1.

  • A signal of A pairs with B's of the same path; --map A=B renames a scope or one signal (the tops pair by themselves when each dump has one). Nothing is matched by its short name.
  • --from / --to a window, --offset B later by that much; --segment tb_test a line per test case, --align case k of B on case k of A (the same case run alone and in a group).
  • --json - the result as JSON, --junit diff.xml a test case per segment for CI; exit status 0 equal, 1 they differ, 2 a usage error.
  • Two testbenches with their scopes named apart: --map tb_a.if_x=tb_b.if_x, and for a signal that moved --map tb_a.sensor_data=tb_b.bif.sensor_data.
  • To look at one case on a page: cut it out, sva vcd b.vcd --from 4783.174us --to 7426.132us --signals 'tb.if_x.*' --out case4.vcd, and give that to Compare….

Who differed first. sva diff A B --rank lists the signals by their first difference: first to differ: tb.c at 10 ns; then tb.a (+8 ns), tb.b (+20 ns) — the order in time only, no cause. Compare… on a page says it in its toast.

The assertions of two runs. sva diff --results a.json b.json compares the results of sva eval --json of two runs: per assertion its failures that are new in B, gone, or moved to another cycle (paired by the start of the attempt), as a table, JSON or JUnit; exit 1 when one is. For CI: the regression that fails somewhere else, the check that stopped failing.
