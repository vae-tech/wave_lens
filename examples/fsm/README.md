# FSM: UART receiver, state names from the dump or from the sources

**Shows** an 8N1 receiver (`uart_rx`, 4 clocks per bit) whose `state` is `uart_pkg::state_t` (`IDLE START DATA STOP ERROR`): a clean frame 0xA5, then a frame with a low stop bit that ends in `ERROR`.
**Build:** `make example EX=fsm` → `$(BUILD)/examples/fsm/fsm.html` from the **FST** (Verilator `--trace-fst` writes the enum table, so the names come from the dump; read by GTKWave's `fst2vcd`, else by the `sva` CLI of `bin/`) and `fsm_all.html` from the **VCD** with `mkconfig.py --sv uart_pkg.sv fsm_tb.sv` (names from the `typedef enum`; for your own dump: `make html WAVES=x.vcd SV="rtl/*.sv"`).
**Config:** written by hand, without any `enum`; `config.style: "questa"` draws vertical edges and narrow bus crossings.
**Structs:** `status` (`uart_pkg::rx_status_t`: state, bit_cnt, valid, frame_err, data) packs the outputs. The FST is written with `--trace-structs`, so it is a struct scope: the `status` view shows `{} status` with its whole 16-bit value on its row and the fields below; the VCD has one 16-bit vector, which `mkconfig.py --sv` takes apart with the fields of the `typedef struct packed` (`fsm_all.html`): the same rows and values.
**Look at:** a bookmark at every state change (on the signal that shows why), `-|-` arrows between consecutive changes labelled with the time spent in the state; the `run` view with the framing error.
**Assertions:** `fsm.sva` — the legal next state of every state, why the state changes, what `valid` and `frame_err` say about it, coverage of a good byte and of a framing error; `sva parse examples/fsm/uart_pkg.sv examples/fsm/fsm.sva` (the package first: it declares the state names), or `make sva-examples`, which also runs them over the dump (`sva eval --scope fsm_tb.u_rx`): all hold except `fsm_demo_short_data`, wrong on purpose (8 data bits take 8 × BIT cycles), which fails for both frames with its trace. In the page: the config binds every assertion to `fsm_tb`, so `fsm.html` opens with them counted (the deliberate failure included).
