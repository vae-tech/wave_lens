PSI5 Manchester Decoder psi5_mc_decoder

Receiver-side Manchester decoder for one PSI5 satellite channel: it takes the current-comparator output of the SATx RXD pin, filters it, recovers 10- or 16-bit sensor frames at 125 or 189 kbps, checks CRC-3 or parity through two redundant shift registers, and reports data or a typed error code to the SPI status logic. This page combines the IP description, interactive block and state diagrams, and the Verilator regression with waveforms pulled from the VCD dump with wavepeek.

1. Overview

PSI5 (Peripheral Sensor Interface 5) sensors answer a voltage sync pulse by modulating a current on the two-wire line. The satellite front-end turns that current into a digital comparator signal, i_sat_rxd_comp, which is the only data input of this IP. The decoder reconstructs the Manchester-coded frame: two start bits, 10 or 16 data bits (LSB first), then either one parity bit or three CRC bits, followed by a gap.

Features

  • Bit rates 125 kbps and 189 kbps, selected by i_sat1_cnf.baudrate; the sampling clock enable (4 MHz or 6 MHz derived from the 12 MHz system clock) is switched accordingly, so all timing windows are expressed in sample ticks and stay identical for both rates.
  • Frame formats 10P, 10C, 16P and 16C (10/16 data bits, parity or CRC-3).
  • Input conditioning chain: 2-FF synchroniser, SYNC-pulse blanking, up/down-counter deglitcher (6 ticks at 12 MHz), 4-sample confirmed-edge filter.
  • Phase-tracking decoder: separate timers since the last rising and the last falling edge, so asymmetric comparator slew does not shift the sampling point.
  • Robustness checks: start-bit spacing, bit timing windows, baud-rate plausibility counter, gap check after the last bit, plus an extra "additional bit during gap" detector.
  • Safety: two redundant 19-bit shift registers compared at end of frame; CRC and parity computed twice (running during reception and recomputed from the shift register) to catch common-mode faults. Test-mode input i_tm_sim_sr_error forces a mismatch.
  • Outputs a one-clock o_sat_data_eof strobe per frame, with o_sat_data_valid for clean data or an error code in o_sat_data (0x7FFA frame / shift-register error, 0x7FFB checksum error, Atic256 variant).
  • o_mc_blank freezes base-current tracking while a frame is being decoded.

The 10-bit formats place the data at bits [15:6] because the shift register fills from the MSB side and only 13 or 11 bits are shifted in. Downstream logic therefore reads the same bit positions for both frame lengths.

4. Manchester decoder FSM

The decoder is a five-state machine evaluated only on sampling-clock ticks. Every timing condition is expressed in ticks of the selected sampling clock (250 ns at 125 kbps, 166.7 ns at 189 kbps); the nominal bit period is 32 ticks and the half bit is 16 ticks. Click a state to list its exits.

Bit decoding rule

PSI5 Manchester coding has the data edge in the middle of the bit cell: a falling edge codes 0 and a rising edge codes 1 (as produced by the sensor model: first half carries the bit, second half its complement). The decoder tracks which edge polarity was the last data edge (r_act_edge_sel) and distinguishes two cases per bit cell:

  • Same-phase transition (same polarity as the previous data edge) arriving 19…43 ticks later: the bit repeats the previous value (rising → 0, falling → 1). Arrival outside the window is a frame error.
  • Opposite-phase transition: accepted when the opposite edge arrives 29…43 ticks after the previous data edge, or (back-up rule) when the same-edge timer reaches 38 while the opposite edge is 9…18 ticks old. The bit toggles and the tracked polarity flips.
  • If the same-edge timer reaches 43 without any decision, the frame is aborted.

Each accepted bit is shifted into both shift registers, into the running CRC-3 (polynomial x³+x+1, seed 111) and the running parity. After the configured number of bits the FSM moves to MC_CHECK_GAP, where the line must stay low for one full bit period.

6. Input filter latency

The comparator edge passes three filters before the FSM sees it. The zoomed trace shows the first start-bit edge of the frame above together with the 12 MHz clock and the 4 MHz sampling enable.

StageSignalDelay after comparator edgeMechanism

Because the filters only delay the signal (they never shorten a pulse that is wider than their window), the decoder's timing windows are measured between confirmed edges and are unaffected by the latency itself. The confirmed-edge filter rejects any pulse shorter than 4 sampling ticks (1 µs at 125 kbps), the deglitcher any pulse shorter than 6 system clocks (0.5 µs).

7. Verification environment

The module-level testbench au_psi5_mc_decoder_tb drives the DUT from a behavioural PSI5 sensor model and checks the decoded word and error status on every end-of-frame strobe.

Sensor model (psi5_sensor_model)

  • Bit clock 8 µs (125 kbps) or 5.3 µs (189 kbps); error.baudrate swaps the rate while the DUT configuration keeps the configured one.
  • Frame: start bits S1 S2 (two rising data edges), data LSB first, then CRC-3 MSB first or one parity bit, then gap. error.gap drives one extra high half-bit in the gap.
  • error.checksum inverts one random CRC bit (or the parity bit). error.shift_register is routed to the DUT's i_tm_sim_sr_error.
  • delay_rising/delay_falling (×0.1 µs) skew one edge polarity to emulate a comparator threshold that is not at the mid-level, i.e. a duty cycle different from 50 %.

Checking tasks

  • tb_send_and_verify_data: expects o_sat_data equal to the sent word (16-bit) or to (data & 0x3FF) << 6 (10-bit); reports $error on mismatch or on a missing eof.
  • tb_send_and_check_error: expects the error code on o_sat_data and the matching o_err_sat bit; a missing eof is only reported with $display, so a silently ignored frame does not fail the run.

9. Reproducing the waves and this page

Everything on this page is generated from one VCD dump. The flow uses Verilator for the simulation and wavepeek (Apache-2.0, Rust) to query the dump without a GUI.

1. Build wavepeek from source

git clone --depth 1 https://github.com/kleverhq/wavepeek.git ~/tools/wavepeek_src
cargo build --release --manifest-path ~/tools/wavepeek_src/Cargo.toml --target-dir ~/tools/wavepeek_target
cp ~/tools/wavepeek_target/release/wavepeek ~/.local/bin/
wavepeek --version        # v3.1.0 used for this page

2. Run the regression with VCD tracing

make trace-vcd            # TRACE=vcd ./verilate_build.sh ; ./verilate_run.sh +trace +wavefile=waves.vcd
# or, with the build directory on the Linux file system (much faster under WSL):
TRACE=vcd OBJ_DIR=/tmp/obj_dir_vcd ./verilate_build.sh
/tmp/obj_dir_vcd/Vau_psi5_mc_decoder_tb +trace +wavefile=waves.vcd | tee sim.log

The testbench dumps the whole hierarchy when +trace is given ($dumpfile/$dumpvars block at the top of au_psi5_mc_decoder_tb.sv). The run takes about one second and produces a 20 MB VCD covering 29 ms of simulated time.

3. Query the dump

wavepeek info   --waves waves.vcd
wavepeek scope  --waves waves.vcd --tree --max-depth 3
wavepeek signal --waves waves.vcd --scope au_psi5_mc_decoder_tb.u_dut --max unlimited

# test windows: every change of the tb_test variable
wavepeek change --waves waves.vcd --on '*' --sample-mode native --max unlimited \
   --signals au_psi5_mc_decoder_tb.tb_test

# decoder result at every end-of-frame strobe (one row per frame)
wavepeek change --waves waves.vcd --scope au_psi5_mc_decoder_tb.u_dut \
   --on 'posedge o_sat_data_eof' --sample-mode native --max unlimited \
   --signals o_sat_data,o_err_sat,o_sat_data_valid,r_state,sr_match

# sparse transition list of one frame for the viewer (JSON)
wavepeek change --waves waves.vcd --from 896008208ps --to 1155176668ps \
   --on '*' --sample-mode native --row-mode sparse --row-values delta --max unlimited \
   --signals au_psi5_mc_decoder_tb.u_dut.r_state,au_psi5_mc_decoder_tb.u_dut.o_sat_data --json

4. Regenerate the page

python3 -I doc/gen_doc_waves.py --waves waves.vcd --out doc/waves_data.json
python3 -I doc/build_doc.py        # injects waves_data.json into template.html -> psi5_mc_decoder_ip.html

Note on sampling modes: the extraction uses --sample-mode native for asynchronous changes (what the dump contains at that timestamp) and the default pre-edge mode only for the clock-aligned bit list in section 5, where values must be those the flops sampled.
